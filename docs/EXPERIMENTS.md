# 第一组实验：从看懂网络到改模型

目标是恢复你对深度学习与工程的掌控感。先预测，再运行，再解释反例。无需按初学者速度重讲全部数学；遇到生疏点，直接回到可运行代码和小张量。

## 0. 在真正优化前确认问题

我们预测训练截止之后的“新物品交互”，而不是曝光点击率。浏览、加购、购买目前都构成一次交互；没有用权重把购买复制成多个样本。`weight` 列仅保留原始行为权重供后续实验，v1 训练不读取它。

查看 overview 的验证分母和 OOV 排除量。思考：把词表从 5,000 扩大后，召回可能变难，覆盖却可能更完整；仅比较过滤后的 Recall 为什么不够？换词表属于换数据快照，应另存数据目录，不能覆盖现有评估。

## 1. 恢复 Embedding、MLP、softmax 和 autograd

代码：`reclab/models.py`；讲义 `02_Retrieval_04`、`02_Retrieval_06`、`05_LastN_01`。

当前模型的张量路径：

```text
用户ID [B] -> user embedding [B,D]
历史ID [B,N] -> item embedding [B,N,D] -> masked mean [B,D]
拼接 [B,2D] -> MLP -> L2 normalized user vector [B,D]
目标ID [B] -> item embedding [B,D] -> MLP -> normalized item vector [B,D]
U @ V.T / temperature -> logits [B,B] -> cross entropy
```

在“特征与样本”读取真实样本，查看 8×8 诊断概率矩阵。对角线是目标；重复目标所在的非对角位置被屏蔽。将 logit 的梯度与 `(softmax - onehot) / B` 对照，先解释负号为何推动正确类别上升。

诊断 batch 由真实训练样本重新组装，仅计算梯度，不更新模型，也不假装是训练过程中记录的原始 batch。

## 2. 第一个消融：有无 LastN

先预测：禁用历史之后，模型为什么仍可个性化？

比较首轮 `baseline-history32` 与 `ablation-no-history`。维度、seed、学习率、batch 和 epoch 相同，只改变 `use_history`。ID Embedding 会记住用户，因此“无历史序列”不等于“无个性化”。

然后固定基础模型，在推荐页“清空序列特征”。这不是前面的重新训练实验：固定模型输入发生分布变化，不能拿这一次列表变化归因于重新训练的效果。

可继续做：序列长度 5 / 20 / 50。均值池化不识别保留窗口内的顺序。将同一组历史逆序，若不跨截断边界，向量应该相同；再讨论为什么 DIN 需要候选相关表示，而不是把它直接替换到独立用户塔。

## 3. 为什么 LogQ 未必涨分

讲义 `02_Retrieval_07` p.11-12。当前损失为 `cosine / tau - log(Q(item))` 后的 batch 交叉熵；Q 来自实际训练目标频率。

比较 `ablation-logq` 与基础模型。先检查正负目标是否偏热门，再同时查看 Recall、NDCG 和 coverage。训练 loss 的绝对数值跨损失定义不一定可直接比较。

这里没有复现原论文的流式频率 sketch/估计器。经验频率在固定小数据集可精确计算，解决的是校正机制验证，不是论文端到端结果复现。

## 4. 参数更多，是否泛化更好

比较 `ablation-history64` 与基础模型，保持数据和优化参数不变。看参数量、训练曲线与验证曲线，不只看最后一轮。种子固定是控制变量，不代表结果有统计显著性；确认趋势后再增加多个种子。

建议下一次你自己做：从 `configs/history32.json` 复制配置，把 name 改为自己的假设，仅改 learning_rate 或 history_len，在页面或 CLI 新建 run。不要覆盖已经完成的模型。

## 5. 召回解释与 MMR

先在 ItemCF 通道点击一个推荐商品，核对它来自哪些历史商品的相似度贡献。然后固定用户/候选预算/模型，对比单路与 RRF 三路融合。RRF 的 k=60 是本实现的工程选项，不是讲义的经验值。

调节 MMR lambda 1.0 / 0.8 / 0.5，观察被重复相似商品挤占的位置。Embedding 相似度是协同行为学出来的；类目不同不保证向量不同，向量不同也不等于内容语义更丰富。没有真实在线反馈，不能声称 MMR 改善点击或留存。

## 后续顺序与验收

1. 扩展 pairwise / pointwise、流行度采样和真正的困难候选日志；用相同验证口径比较。
2. FM 数学等价验证、DCN V2、MLP 排序；先定义样本、特征、标签与观察窗口。
3. DIN attention 可视化、SIM 长序列筛选；比较质量和延迟。
4. MMoE 的 gate 与任务梯度；保留不提升的结论。
5. Swing / UserCF / MF / 自监督召回，再到 Deep Retrieval 的路径结构。
6. DPP 的小全集穷举与快速贪心、规则约束、冷启池与流量模拟。
7. 稳定实验分桶、曝光日志、实时特征回放和原 lakehouse lab 的独立 adapter。
